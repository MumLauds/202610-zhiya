# 独立 Staging 接入计划

推荐先在现有 FastAPI 应用按家长确认回答入口集成。旧版 Agent 路径保持默认服务，Agent 2.0 按环境与受控名单启用。实验模型与拟发布目标均固定北京 `qwen3.8-flash`。

| 环境 | 目标 | 隔离与证据 |
|---|---|---|
| Development | 纯逻辑、恶劣响应和拒绝路径 | 合成夹具、Mock、独立本地 SQLite |
| Local Integration | 同一业务 API 连接浏览器、会话和安全回执 | 真实应用进程、测试账号、临时库。接口可跑真实本地 HTTP，供应商模式明确 |
| Staging | 独立 HTTPS 应用与真实北京 Flash、语音验证 | 独立主机或明确网络隔离的资源与 DNS、Cookie/origin、协议、Compose project、卷、备份、日志、只读管理角色、供应商空间或受控专用 Key |
| Controlled Pilot | 经监护人授权的受控家庭 | 通过 Gate 2，独立 feature cohort，批准的数据地域与预算，单独值班及回滚。默认仍为旧路由 |
| Production | 审批后的逐步公开启用 | Gate 3，独立回执和指标，按已批准版本发布 |

### 建设与交付顺序

1. G07/G08/G09 与前端、QA 审定 [业务合同](data-flow-and-api-contract.md)。确认启用入口、版本标记、请求键、授权、预算、断开、允许的状态、TTS 和小结兼容。必要 DB 改动走独立迁移审批。
2. 仅给测试账号与合成夹具接新流水线。默认关闭。启用路径需验证常态返回、可重放回执、跨账号拒绝、显式模型失败及旧版回退。对照旧路由的真实表现单列。
3. 运维准备独立 HTTPS、专用凭证和真实供应商允许列表。将 release SHA、前后端镜像 ID、Agent/Prompt ID、合成集哈希和测试矩阵记录在 Staging 回执。先核对环境隔离和缓存，再运行真实链路。
4. QA 在桌面 Chrome/Firefox、移动 iOS Safari/Android Chrome 实测创建、开始、对话、翻页、回翻、暂停、恢复、完成、刷新、断网和小结。语音并行验 MIME、音频播放、授权撤销和旧音频释放。报告标明硬件/浏览器/网络条件以及是否调用真实供应商。
5. 按 [验收计划](production-test-plan.md) 保存可重复证据，缺证据项标 BLOCKED。模拟故障可验证分支，正常请求和合成授权数据的真实供应商/浏览器环节必须分别有记录。
6. Gate 1 通过后完成隐私、安全、账单、限额、值班与回滚演练。Gate 2 签字后，建议最多 10 个授权家庭、7 天受控试运行。具体人数、预算和退出条件由产品和数据负责人批准后生效。

### 合成数据和开关

使用独立账号、儿童档案、授权和虚构绘本，测试旧版与新版会话并行。每次运行使用干净的临时数据库或可重建种子，访问计数、授权与过期凭证为独立资源。允许写入的域名/数据库/媒资和凭证归属通过启动时配置校验。关闭 2.0 开关走 [回滚步骤](deployment-and-rollback.md)，验证阅读和报告可以继续。

## 可审查配置

Compose 项目 `zhiya-agent-stg` 默认关闭。HTTPS 绑定本机，Caddy 返回私有缓存头，应用只挂独立 SQLite 卷。初始化限定合成测试绘本。名单及北京 Flash 专用凭证待部署获批后由授权值班员配置。真实独立环境、私有网络、浏览器矩阵及回滚演练仍为 BLOCKED。 [配置和手册](../../infra/staging/README.md)

## PR 容器验证与真实工作空间

PR 工作流使用独立项目和合成账号，通过 `bash infra/staging/smoke_ci.sh` 构建镜像、启动 Compose、初始化 SQLite、回读合成绘本、校验 Caddy 私有 CA 和 HTTPS、核对功能与出站两个名单、检查运行时北京 Flash 配置并演练关闭。代码审查阶段使用合成占位凭证验证配置，本机隔离合成数据已通过北京默认业务空间完成两轮真实请求。需在非默认测试业务空间及专用 Key 下复跑。独立云 Staging 仍需批准的测试地址、账号与运行记录。

## PR #97 Gate 1 本轮证据

CI 依次验证允许列表、撤销输入授权和 Agent 关闭三个阶段。独立云环境获批后仍需运行同一阅读、隔离和回滚流程。真实 Flash 采集、环境边界和证据见[Gate 1 验收](gate1-staging-validation.md)。
