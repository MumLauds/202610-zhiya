# 数据流与 API 契约

以下映射是供 G07/G08/G09/G11/G12 评审的建议合同。正式 URL 和既有字段以现行契约为准。第一阶段以 API-015 的家长确认作答为接入点，保留 API-016 的本页发问权限与原合同，API-017 仍负责既有引导。

## 当前业务 API

| API | 请求/约束 | 读取或写入 |
|---|---|---|
| 011–014 | 创建、列表、详情、删除。详情 `session_id`，删除仅本人家长 | API-013 提供固定版本、状态、访问路径、`currentPage`、`revision`、已保存事件和可见报告 |
| 015 | `session_id`, `eventType`, `pageNumber`, `expectedRevision`, `clientEventId`。家长文本、儿童限定选项 | 首次事件通常 201，成功重放 200。家长作答可有 `replyText` 与 `followupQuestion` |
| 016–017 | 当前页、修订号、事件键。016 家长确认题，儿童固定问题。017 热身及理解反馈 | 既有 `ASK` 或引导事件。输出和授权继续按各自角色投影 |
| 018–019 | 有效分支或结束意图、修订号及事件键 | 更新正式进度/结束，报告以历史事件和实际已读为准 |
| 020–023 | 模式切换/家长解锁/语音识别/合成。权限由服务端检查 | 合成答复绑定已保存的可播放事件，与浏览器发起的原始草稿无关 |

## 建议时序

1. 以 Cookie/CSRF 和授权解析 principal，验证会话归属、版本、页、角色、活跃状态和修订号。预留幂等键及执行 token，以服务端页访问事件为快照锚点。
2. 构建当前已审核书页、访问前缀、受控线索和已核验有限历史。地址、姓名、账号、设备标识、授权和原始音频留在必要的本地业务域。当前 API-015 的作答原文留在服务端。任何放宽出站内容都要另审。
3. 短事务写入既有事件和可恢复的规则回应后释放 DB。仅按同一请求键发起一次受预算限制的生成。过载、断开、撤权或模型失败按原因处理。
4. 严格验证草稿结构、事实依据、问题格式、年龄边界和输入/输出安全，以 token、访问事件和 revision 再核验。有效回执与执行结论原子写入，再返还前端。过期或越权结果丢弃。迟到输出不得触发音频或改新页。
5. 刷新或未知结果先读 API-013，用户按现有同键重放规则继续。报告仍从已保存阅读事实生成。

| 协议 B | API 映射建议 |
|---|---|
| `reply` | 经校验的 `replyText`，与既有追问后缀规则兼容。正文只呈现实际保存的投影 |
| `followup_question` | 真正允许并通过额度/去重的追问才映射 `followupQuestion`。其他动作省略 |
| `RESPOND/ASK_FOLLOWUP` | 业务对话 `CONTINUE`。追问须按现有合同决定修订号 |
| `LISTEN/PAUSE/CLOSE_TOPIC` | 提案为可选、版本受控的对话状态，依次映射 `LISTEN/PAUSE/END_TOPIC`。阅读业务 `IN_PROGRESS/FINISHED` 保持由阅读动作决定 |
| `REPLY_ONLY` | 完整原正文加无追问，代表投影结果。客户端可忽略示例性状态字段继续使用正文 |
| 回退/接管 | 保留安全规则回应，告知家长可继续阅读。原因进入脱敏运行回执，必要的可操作 UI 错误用既有错误码 |
| 原始模型响应、prompt、token、供应商 request ID | 内部诊断只留必要的安全元数据。儿童、家长和 TTS 均从业务回执读取，不返回原始模型草稿 |

候选可选对象如 `agentReceipt={version,state,decision}` 需同步 API-015 与 API-013 schema，并经旧桌面、移动兼容矩阵批准。没有合入的字段由既有兼容字段承载。字段命名和存储方案在 Gate 1 签字后实现。内部回退原因及 HTTP 错误映射见 [观测](observability-and-cost.md)。

页面回看与服务器再次到达分别测试。只读回看不会移动服务端游标。正式 `PAGE_CHANGED` 校验默认下一页，合法返回型分支以 API-018 保存的实际路径为准。若产品需要新增可交互的任意回翻，先审其资源可见范围、事件含义与会话恢复。
