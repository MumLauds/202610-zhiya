## 维护约定

- 每项使用稳定编号 `DCL-001` 起顺序递增；变更日期取实际发生日期，未知时填“待补充”。
- “已修订，待评审”表示已有文档或数据调整；“待决策”表示结论尚未确定。团队确认后补充确认人、日期及 PR 或评审记录，不能用代码合并或本文件建立代替设计审批。
- 设计确认、实现交付和测试通过分别记录。变更被替代时保留原记录，并链接后续编号。
- 本文件保留原因和决定摘要。现行术语以[公共术语表](glossary.md)为准，接口以[接口契约](../design/api-contract.md)及其 JSON 示例为准，物理表结构以[数据库设计说明书](../design/妈妈夸我说的队_数据库设计说明书.pdf)为准；决定变更后同步相应来源。

## 已有变更整理

### DCL-001｜限定本期有限续写范围

- **变更日期 / 状态：** 2026-11-04；已有范围确认记录，团队最终确认待补充。
- **需求与用例：** FR-17，P1；TC-FR17-04、TC-FR17-05。
- **原因与处理：** 明确有限续写是否纳入本期及其边界。现有契约记录本期包含亲子模式下的固定源快照、审核新版本和原子切换；整本及各阅读路径仍为 4～6 页。
- **影响范围 / 兼容性：** M05、API-025 → API-026 → API-011，以及源会话、故事版本和续读位置。普通阅读主链无需触发续写；前后端须按冻结后的版本与修订号约定完成切换。
- **负责角色：** 设计修订者林鑫；实现角色沿用业务后端与领域 Agent 分工，具体执行成员待团队安排。
- **确认依据：** [接口契约“本期有限续写范围”](../design/api-contract.md#本期有限续写范围)记录用户于 2026-11-04 确认范围；原资料仍保留组长确认待办，未记录团队最终确认人和日期。
- **验证与后续：** 实现后验证切换成功时新旧会话原子变更，失败时源会话可继续使用；业务验收结果待补充。

### DCL-002｜种子绘本保持草稿，补齐资源后再发布

- **变更日期 / 状态：** 2026-11-09；已修订，待评审。
- **需求与用例：** FR-11；TC-FR11-01。
- **原因与处理：** 20 个团队原创样例版本缺少逐页素材和审核记录，已改为 `DRAFT`；20 张已交付图片作为封面。当前包含旧联调用例在内的 21 个版本均为草稿。
- **影响范围 / 兼容性：** M08、API-024/028、`story_versions`、`story_pages` 和后台初始状态。不能再将本批种子视为已发布书架数据；逐页资源须转换为受控媒体资源键。
- **负责角色：** 知识工程交接素材与授权，业务后端承接审核与发布。
- **确认依据：** [接口与数据交接核对](../design/api-contract-review-v0.4.md#本轮遗留问题处理)及[种子说明](../../data/seed/README.md)。团队确认人、日期和审批记录待补充。
- **验证与后续：** 已有交接记录完成草稿状态等静态核对。实现后验证缺图或未审核时拒绝发布，审核人、审核时间与发布状态在同一事务落库；实际素材补齐和发布验收待完成。

### DCL-003｜统一知识适用标签、版本修订与停用规则

- **变更日期 / 状态：** 2026-11-09；已修订，待评审。
- **需求与用例：** AI-01、AI-07；TC-AI01-01、TC-AI07-01。
- **原因与处理：** 明确全龄知识、任务标签及知识停用的共同含义。全龄使用 `ageBand: null`；接口 `taskTypes` 与种子 `task_types_json` 使用同一组大写枚举；检索仅使用当前有效的 `APPROVED` 版本。
- **影响范围 / 兼容性：** M04、M08、API-029～031、`knowledge_items`、`event_evidence`、数据库设计表 4-19。知识修订产生新 ID，历史证据仍引用实际使用的旧 ID；新草稿不替换当前批准版。停用操作和冲突响应按现行契约执行。
- **负责角色：** 领域智能体与知识工程核对检索条件和来源，业务后端承接版本事务。
- **确认依据：** [公共术语与枚举](glossary.md)、[接口契约](../design/api-contract.md#小结历史版本与知识修订)及[交接处理记录](../design/api-contract-review-v0.4.md#本轮遗留问题处理)。团队确认人、日期和审批记录待补充。
- **验证与后续：** 已有交接记录完成标签、全龄与停用示例的静态核对。实现后验证停用后不再命中新检索、历史引用仍可追溯、旧版本 ID 冲突及混合停用字段拒绝等场景。

### DCL-004｜增加阅读小结的启动恢复规则

- **变更日期 / 状态：** 2026-11-09；已修订，待评审。
- **需求与用例：** FR-09、FR-12；TC-FR09-01、TC-FR12-01。
- **原因与处理：** 进程中断可能留下 `PENDING` 小结。首版单工作进程启动时，在应用就绪前将遗留小结条件更新为 `FAILED`，保留事实摘要，活动数组置空；恢复不调用模型，也不改写原结束响应。
- **影响范围 / 兼容性：** M03、M07、API-013/019、`reading_reports`、`request_executions`。同键仍重放原响应，前端通过 API-013 读取当前小结；此恢复约定依赖单工作进程部署，改变部署方式时须重新评审。
- **负责角色：** 业务后端承接恢复和幂等，领域智能体承接正常生成。
- **确认依据：** [接口契约](../design/api-contract.md#小结历史版本与知识修订)及[交接处理记录](../design/api-contract-review-v0.4.md#本轮遗留问题处理)。团队确认人、日期和审批记录待补充。
- **验证与后续：** 已有交接记录核对了恢复响应示例。实现后执行结束提交、中断、重启和重复请求用例，检查终态与事实记录保留，且模型调用次数不增加。

## 后续追加模板

复制以下模板并使用下一个未占用编号；仅在有证据时填写“已确认”或“验证通过”。

```markdown
### DCL-XXX｜变更或冲突主题

- 变更日期 / 状态：
- 需求与用例：FR / AI / NFR / TC 编号；不适用时说明原因。
- 原因与处理：原有问题、考虑的方案、最终决定或待确认问题。
- 影响范围 / 兼容性：模块、接口、表、文档版本、图号及迁移影响。
- 负责角色 / 人员：
- 确认依据：确认人、日期、PR 或评审记录链接；未确认则写待确认。
- 验证与后续：已完成检查、结果证据及尚未完成事项。
```
