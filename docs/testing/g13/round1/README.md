# G13 第一轮系统联调

2026 年 11 月 19 日，Chrome 从家长登录、创建档案、选书一直走到重新登录后读回同一次共读的小结。Firefox 在录音上传时返回 `422 AUDIO_INVALID`，改用文字输入后也能读回小结。首轮受测提交为 [6e04a14](https://github.com/MumLauds/202610-zhiya/commit/6e04a14292c801f72e14247dfb73b89642d0de85)。

## 环境与数据

- 北京时间 08:17 启动 Chrome 154.0.8037.98，08:18 启动 Firefox 153.0。两次各使用独立浏览器配置、独立 SQLite 库和同源回环 HTTPS，证书正常校验，连接使用 TLS 1.3。
- 使用该提交的 Vue 生产构建、FastAPI 认证与 CSRF 校验、绘本和会话接口、FFmpeg 音频转换及 SQLite 读写。两个浏览器都使用虚拟麦克风。账号、档案和三页绘本《纸船停在哪里》是隔离测试数据。测试审核角色将该绘本设为可读，版本 ID 为 9100。导入的 21 个草稿版本保留原状态。
- 在供应商 HTTP 层模拟 ASR、TTS 和小结模型。ASR 返回固定转写，TTS 返回 2 秒、24 kHz 测试音，小结模型返回 `REVISIT_PAGE`。本轮保留了真实的上传、解码、播放和小结落库结果，正式绘本授权与真实供应商效果待验。

## 操作与结果

| 页面操作 | 两次运行的结果 |
| --- | --- |
| 登录家长空间，建立儿童档案 | 两个浏览器均成功。家长会话 Cookie 带 Secure 和 HttpOnly。每个库各有一条阅读会话，始终关联本库同一账号、档案和绘本。 |
| 选书、翻到第 2 页、回看第 1 页、返回第 2 页 | 创建会话返回 201。回看时服务端仍在第 2 页，朗读入口禁用。返回进度页后恢复。每个库各写入一条 `STARTED` 和一条 `PAGE_CHANGED`。 |
| 朗读第 2 页 | 两个浏览器均收到合成请求 201、受控音频读取 200，并播放至“朗读完成”。 |
| 录音、识别、校订并确认 | Chrome 上传成功，经 FFmpeg 解码为 16 kHz 单声道；模拟转写“小船停在哪里”可改为“纸船为什么停在绿叶旁？”并确认，关闭后文字清除。Firefox 上传 Ogg 数据却声明 WebM，返回 422；页面“直接输入文字”可完成确认。 |
| 在第 2 页结束三页绘本并刷新小结 | 两库会话均为 `FINISHED`，修订号 3，已读页为 `[1, 2]`，小结状态为 `READY`。结束后只能回看已读的两页。 |
| 查看历史、退出后重新登录 | 两个浏览器均在历史页看到“浏览 2 页 · 已完成”。本版本该记录没有详情按钮；通过原阅读会话地址重新打开，可读回已保存的相同小结。 |
| 加载书架第二页 | 主流程后分别追加 30 本专用分页夹具，第一页返回 30 本，第二页返回 1 本，“加载更多”随之消失。 |
| 儿童提问、回答播放与保存、反馈引导 | 在首轮提交上，后端尚未注册 API-016 或 API-017，页面禁用理解反馈。确认的文字仅在当次弹窗显示。API-017 后续随 [PR #47](https://github.com/MumLauds/202610-zhiya/pull/47) 合入。 |

## 复核

两个浏览器分别留存一份脱敏 JSON。`browserSteps` 和 `browserRequests` 记载操作和接口结果，`checks` 包含数据库会话、事件顺序、外键检查与供应商模拟结果。两库外键检查均通过。[Chrome 首轮数据](chrome.json) · [Firefox 首轮数据](firefox.json)

Firefox 首轮失败时按声明的 WebM 解码得 0 字节，按真实容器解码得 47,360 字节 PCM。后来在 `ce8b2a2` 复现，在 `9be5439` 上分别用 Firefox、Chrome 验证上传、解码与编辑确认。三次后续运行的数据单独保存。[PR #51 双浏览器验证](../voice-51.json)
