## 知识草稿与隔离库验证

[八条 API-030 草稿](../../../data/seed/course_knowledge_drafts.json)从各书固定提交的分页稿、互动提示中提炼观察与复述方法。每条保存书号、页码、原稿链接和适龄分段，选用书目中的一个具体主题，支持 `GUIDANCE` 与 `RETRIEVAL`。同主题可跨书命中，因此提示根据当前页举证，不将某本书的情节写作其他书的答案。既有 20 条基础知识仍按各自的状态处理。此交接包采用本次交付候选中的内容管理接口，部署后可在已有库逐条暂存，默认种子导入不会触发批准。

1. 内容管理员可逐条把 JSON 数组中的对象原样提交给 `POST /api/v1/admin/knowledge-items`，每个对象均为 `DRAFT`。重试使用同一 `Idempotency-Key`，例如 `course-v1-KN-BOOK-002`。如键名已存在，先用 API-029 读回并比较版本、来源及状态，再决定是否修订已有记录。
2. 审核时打开原稿定位页，核对年龄、主题及提示。真实通过后由内容管理员使用 API-031 创建批准版本，并将结论登记到交付记录。API-017 用 `GUIDANCE` 检索，领域服务的故事回答使用 `RETRIEVAL`。[检索任务映射](../../../backend/app/agent/service.py) · [引导读取条件](../../../backend/app/services/reading_agent.py)
3. 复跑命令为 `cd backend`，再运行 `python -m pytest -q tests/test_course_knowledge.py`。用例在全新的临时 SQLite 库导入项目种子，注册隔离账号并仅在测试库赋予管理员角色，调用 API-030 创建草稿、以同一键重放，再由 API-031 模拟批准。没有调用外部模型或修改已部署数据库。

实测两项回归通过。审核前，以每本书的实际年龄、完整主题和第 1 页正文查询，两类任务共 16 组均无命中；模拟批准后，16 组分别命中表中对应的同源知识。每条草稿重放仍指向原知识 ID，八条模拟批准记录均为第 2 版。无匹配主题、全龄查询或 `SAFETY` 任务均未误用这些条目。该轮确认来源追溯与检索结果；问答输出质量及正式签核需分别验收。[来源与检索回归](../../../backend/tests/test_course_knowledge.py)
