# 课程候选版演示与验收

从同一个完整 Git 提交构建前后端，将本轮记录保存在仓库外以该 SHA 命名的目录。构建后用 `git rev-parse HEAD` 和 `git status --short` 核对版本与工作树。旧版脚本、截图和评分表保留其原测日期。最终签收暂缓。

| 环节 | 现场操作 | 观察并记录 |
| --- | --- | --- |
| 内容准备 | 管理员核对书页、图片、许可备注和知识来源，按清单逐项维护。课程审核给出结论后，再对正式库执行发布或批准。 | 书号、版本、配图、知识条目及审核人。隔离库的自动批准只用于技术联调。[八本预审与知识清单](../g13/course-content-review.md) |
| G13 主动问答 | 家长打开《小狐狸的雨伞》第 1 页，点“问问芽芽”，输入“小狐狸站在哪里？”，确认文字并提交。刷新后读回回答，再播放。 | 记录会话、回答事件、命中来源。重发同一请求只读回原事件。分别记录真实模型、合成、识别及音源。 |
| G14 模型对比 | 用同一案例集执行通用与领域两组，逐例核对原始输出和检索条目。 | 记录完整 SHA、planHash、runId、计划/有输出的数量、缺失案例及检索命中数。两位评分人独立打分后才公布质量结论。 |
| G15 电脑与手机 | 部署者从同一 SHA 构建两个镜像，给出两侧修订号和镜像 ID。分别用电脑及实体手机访问 HTTPS，登录、选档、开读、翻页、刷新、主动提问、录音确认、结束，查看历史与小结活动。 | 记录入口、时间、设备/系统、浏览器、会话、内页图、录音权限、刷新和历史结果。实际设备与桌面模拟分行记录。 |

### 本地复跑 G13 与 G14

需要运行仓库后端的 Python 环境、Python Playwright、Chrome、OpenSSL、FFmpeg 和前端锁文件对应的依赖。在独立的干净候选工作树构建前端；以下 PowerShell 命令从仓库根目录执行。`$evidence` 初次运行时应为未使用的目录，父目录须已存在。

```powershell
$candidate = (git rev-parse HEAD).Trim()
$evidence = Join-Path (Split-Path (Get-Location) -Parent) "course-$candidate"
Push-Location frontend
npm ci
npm run build -- --mode public
Pop-Location
python qa/p6/course_rehearsal.py prepare --directory $evidence --tested-commit $candidate
```

在项目配置环境中执行以下命令。G13 使用真实文本和语音服务，音源是系统刚合成的故事回答。G14 计划 24 例、两种条件，最多 48 次文本调用。两项共用上一步新建的隔离数据；管理员身份及批准动作均为测试夹具。不要对公网数据库执行准备步骤。

```powershell
python qa/p6/course_rehearsal.py browser-live --directory $evidence --tested-commit $candidate
python qa/p6/course_rehearsal.py model-live --directory $evidence --tested-commit $candidate
```

若上一次执行中断，保留其报告和费用记录。重验 G13 使用新的证据目录；G14 汇总可以用 `--results` 指定该轮的 JSONL。缺少有效输出、人工评分、正式审核或同版公网真机记录时，将对应栏保留为待验证。
