## 一、演示目标

用一条真实可复现的链路证明：

1. 家长账号、幼儿档案、绘本、共读会话、翻页、结束、历史是**真实持久化**的；
2. 会话写入具备**幂等与冲突控制**，不是“点一下换一张图”的假演示；
3. 儿童模式有**授权范围、时长、家长解锁、旧凭证吊销**；
4. 语音服务未配置时**安全回退**，不阻断图文共读；
5. 测试不是“全过”的口号：黑盒状态与缺陷分别以验收记录、缺陷台账为准；
6. 模型对比有**24 例评测集与双人评分规则**，没密钥就不编效果数字。

## 三、A 轨：接口真实演示（当前可执行）

### 3.0 启动演示驱动

```bash
python qa/p6/demo_flow.py \
  --base-url http://127.0.0.1:8765 --allow-http \
  --account p6demo --password 'Zhiya-demo-2026' --pause
```

`--pause` 会在每一步后等待回车，便于讲解。若现场网络/限流异常，改用 `--base-url https://...` 或展示预跑输出。

### 3.1 分镜与话术

#### 0:00-1:00 开场

**屏幕**：测试文档封面 / 仓库 README。

**话术**：

> 我是刘俊延，负责知芽的测试验收、模型对比、缺陷跟踪、公网验收和演示脚本。今天不按 PPT 讲功能，而是用一条真实链路说明三件事：已经做对的、还没做完的、以及我们怎么证明。
>
> 知芽是面向 3～6 岁亲子共读的 Web 软件，领域智能体是差异点，硬件是可选扩展。P6 的验收基线是 SRS 的 AC-01～AC-15。

#### 1:00-1:40 健康检查

**操作**：`demo_flow.py` 步骤 1。

**预期输出**：

```json
{"data":{"status":"ok"},"requestId":"..."}
```

**话术**：

> 健康检查只证明应用和数据库就绪，不证明模型或语音可用；这两类依赖我们单独验证，避免把“服务活着”说成“业务全通”。

#### 1:40-3:00 登录与档案

**操作**：步骤 2～3。

**预期**：登录 201；档案 `childProfileId`、`ageBand=AGE_4_5`、兴趣、10 分钟。

**话术**：

> 会话使用 HttpOnly + Secure + SameSite=Lax 的 Cookie，写请求还要 CSRF 令牌。档案只存年龄段、兴趣和时长，不强制真实姓名和生日，符合隐私最小化。
>
> 注意：本地是 HTTP，浏览器不会回传 Secure Cookie；测试脚本用 `--allow-http` 在客户端侧规避，生产必须 HTTPS。

#### 3:00-4:30 绘本馆

**操作**：步骤 4。

**预期**：12 本可用，选中《逃家小兔》v1，6 页。

**话术**：

> 种子数据默认全部是 DRAFT，这是内容治理要求，不是 bug。演示前我们通过审核脚本把 12 本置为 PUBLISHED、20 条知识置为 APPROVED；生产环境应走管理员接口，目前 API-027/028 还没实现，这是缺陷台账里的 P1。
>
> 详情里的 `coverRef` 和 `imageRef` 目前是 null，因为受控媒体解析还没做，前端只能显示占位图；这也是 P2 缺陷，不藏着。

#### 4:30-7:30 会话、开始、幂等、翻页

**操作**：步骤 5～7。

**预期**：
- 创建：`status=CREATED, revision=0`；
- 开始：`revision=1`；
- 重放同一 `clientEventId`：200，`interactionEventId` 与 revision 不变；
- 翻页：`revision=2, currentPage=2`。

**话术**：

> 这里是我们和“Demo 级作品”的区别：每个写事件都有 `clientEventId` 和 `expectedRevision`。同一个键重放返回原响应，不会重复写；同一个键改内容返回 409 `IDEMPOTENCY_CONFLICT`；拿过期 revision 写返回 409 `SESSION_CONFLICT`。
>
> 为什么重要？家长在地铁里网络抖动，前端自动重试时不会把孩子翻页记两遍，也不会把阅读进度写乱。

#### 7:30-9:00 结束与小结

**操作**：步骤 8。

**预期**：`FINISHED`；`report.status=PENDING`（无模型时后台转 FAILED）；`summary='本次共读阅读了第 1、2 页。'`；`activities=0`。

**话术**：

> 结束是一个事务：终态、事实摘要、小结占位和可重放响应一起提交，然后才在事务外调模型。模型失败不会把事实摘要弄丢，也不会让页面永远“生成中”。
>
> 但 `activities` 还是空的，FR-10 的亲子活动材料和步骤没做完，所以 AC-09 我们记的是阻塞，不是通过。这就是“0 失败但 6 阻塞”的含义：已实现的都过了，没实现的不冒充。

#### 9:00-11:00 儿童模式与家长解锁

**操作**：步骤 9～10（可切到无痕窗口展示儿童视角）。

**预期**：
- 进入 `CHILD_SOLO`，签发儿童授权，120 秒；
- 儿童修改时长：403 `FORBIDDEN`；
- 家长密码解锁：200，签发新家长会话；
- 旧儿童 Cookie：401 `AUTH_REQUIRED`。

**话术**：

> 儿童模式不是“加一个卡通皮肤”，而是权限模型：家长选定绘本范围、时长；儿童只能读授权内容，不能改设置、不能看家长档案；到时间或家长解锁后，旧凭证立即失效。
>
> 注意 API-020 会吊销发起设备的家长会话，这是契约要求。现场演示要用另一个浏览器保留家长入口，否则你会以为“家长被踢下线”是 bug。

#### 11:00-12:00 语音安全回退

**操作**：步骤 11（默认不调用付费 TTS）。

**默认演示**：展示归档的 503 `TTS_NOT_CONFIGURED` 和文字回退。只有显式传入 `--voice` 才会发起合成。

**话术**：

> 语音没配置时，合成接口安全失败，前端应回退为文字回答，图文共读不受影响。我们没有为了演示去伪造音频；真实 ASR/TTS 的准确率和音质是另一类验收，需要单独授权和样本。
>
> 六声线慢速样本此前已在容器里真实合成并试听通过，但那不等于完整 AC-07。

#### 12:00-13:30 测试与模型对比、缺陷台账

**屏幕**：切到 `qa/p6/reports/acceptance-latest.md`、`defect-ledger.md`、`model-compare-summary.md`。

**话术**：

> 展示首页列出的本轮黑盒统计。AC-14 只验证了单条分支、重放和修订冲突，仍缺同一决策点两个不同后续、节点上限及无环检查。2026-11-18 的后端回归 198 项、199 个子用例，行覆盖率 96%；前端 71 项测试通过。
>
> 12 条缺陷：P1 5 条、P2 7 条、P0 0 条。P1 集中在 Agent 路由、原创故事/审核、活动和公网；P2 是浏览器 E2E、安全头、CORS、媒体、语音偏好、CI 和测试分支内容。
>
> 模型对比我们准备了 24 例、三个条件、6 个维度、两位评分人。但现在没有 `MODEL_API_KEY`，所以只做了 dry-run，报告里明确写“未执行”，没有编“提升 XX%”。有密钥后一条命令就能跑，48 次调用封顶。

#### 13:30-14:30 结论与边界

**话术**：

> 结论分三层：
> 1. 后端已实现主链路质量较好，可以答辩演示；
> 2. P6 整体不通过——AC-05/06/09/11/13/14/15 还阻塞；
> 3. 公网和真实模型对比待部署/待密钥，我们不会把待执行写成通过。
>

## 五、现场故障回退

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 登录 429 | 同一 IP 15 分钟超过 10 次 | 等待窗口结束；重启本地服务；换手机热点 |
| 书架为空 | 未审核发布种子 | 提前准备；现场不要改库，展示预跑截图 |
| 儿童模式后家长被踢 | API-020 吊销当前设备会话 | 用另一个浏览器/设备保留家长入口 |
| TTS 503 | 未配置或未授权 | 正常演示“安全回退”，不要现场配密钥 |
| 模型无输出 | 无 `MODEL_API_KEY` | 不演示真实生成；讲评测方案与待执行状态 |
| 公网打不开 | 未部署/证书问题 | 明确说 AC-11 阻塞，展示本地证据 |
| 前端空白 | 前端未启动或 Vite 代理未指向后端 | 启动 `npm run dev` 并把代理指向后端；否则切 A 轨接口演示 |

## 六、Q&A 预案

**Q1：为什么 0 失败还有 6 个阻塞？算通过吗？**
> 不算。0 失败只说明“已经实现的接口没有发现功能性错误”；6 个阻塞是接口、内容或部署不存在，无法判定。P6 整体结论是不通过，阻塞项在文档 5.8 和缺陷台账里逐条列了责任方。

**Q2：模型对比为什么没有结果？**
> 当前环境没有 `MODEL_API_KEY`。我们完成了 24 例评测集、三条件设计、双人评分表和执行脚本，但不会用 dry-run 冒充结果。有密钥后 48 次调用、20 秒超时、不自动重试，结果和评分表都会留档。

**Q3：怎么保证不是只测了顺利路径？**
> 有跨账号、CSRF、过期 revision、同键不同请求、儿童越权、错误 Content-Type、缺字段、未知路由、方法不允许等反例；后端回归 198 项、覆盖率 96%。公网和真实供应商是另外的阻塞项，没有混在一起算。

**Q4：种子全是 DRAFT，演示数据是不是假的？**
> 种子是开发草稿，审核发布是内容治理流程。演示前用脚本把 12 本置为 PUBLISHED、20 条知识置为 APPROVED，并写入审核人和时间；生产应走管理员接口，目前该接口缺失，已记为 P1 缺陷。

**Q5：前端没做完，怎么证明软件能用？**
> 最新 main 已有完整前端页面，71 项组件/Store 测试与构建通过；但浏览器端到端还没有自动化，AC-04/07/11/12 的 UI 部分我们只记为部分通过。答辩现场会人工走一遍，并保留截图，不把页面可达说成完整验收。

**Q6：安全做了什么？**
> 会话 Cookie 三重属性、CSRF、跨账号 404、儿童权限、旧凭证吊销、错误 envelope 不含敏感信息、日志不记录正文/密钥；安全响应头和 CORS 还没做，记为 P2。

**Q7：为什么登录有限流，影响验收吗？**
> 10 次/15 分钟是防暴力破解的预期行为。一次完整验收约 5 次登录，连续重跑会 429；测试脚本把 429 记为阻塞而不是失败，并提示等待或换出口。
