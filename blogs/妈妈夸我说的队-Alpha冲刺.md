## 二、五个问题与改进方案

| 发现的问题 | 本轮怎么改 | 预期效果 |
|---|---|---|
| 原型里能点，不等于前后端已经实现 | 不再扩展新页面，围绕真实账号、绘本、会话逐段接接口 | 演示真实业务流程，而不是静态页面或 Mock |
| 账号、绘本、会话、Agent、语音、儿童权限依赖多，容易接口不一致 | 以接口契约为准，先核对数据模型与错误码；跨模块修改先评审 | 降低联调返工，问题能定位到具体接口 |
| AI 可能脱离当前故事，生成不合适内容 | 接入知识检索、适龄提示词、权限校验与降级策略，输出记录引用依据 | 生成结果更可控、可追溯 |
| 绘本图片、审核状态与数据库数据不一致 | 完成 104 页内页映射、内容审核与合法可读性核验，缺图显示真实错误 | 展示内容与数据库状态一致 |
| 测试与部署准备不足，现场只能"跑一遍看看" | 从开发初期同步写用例，安排联调、日志、备份与恢复预演 | 交付可运行、可复测，问题有台账 |

## 三、冲刺目标与范围

总目标：做出一个能完成大部分核心功能的知芽 Demo——家长进入系统、选择儿童档案、浏览绘本、阅读翻页、体验互动、查看记录或小结，全程可真实操作。

| 级别 | 本轮目标 | 验收方式 |

| P0 必做 | 家长登录与儿童档案 | 演示账号登录，档案与业务数据一致 |

| P0 必做 | 基础智能互动 | 至少一种与当前情节相关的提问、反馈或问答；模型不可用时有降级 |
| P0 必做 | 页面体验与演示稳定性 | 首页、绘本馆、阅读页、记录页切换清晰，现场无阻断性错误 |
| P1 争取 | 语音朗读与语音提问 | 录音、转写确认、朗读；失败可回文字 |
| P1 争取 | 儿童模式、故事分支、原创故事 | 至少可演示入口或受控操作，未完成部分如实标注 |
| P1 争取 | 本地 / HTTPS 部署与测试记录 | 答辩电脑可运行，保留测试与备用环境 |
| 拓展 | ESP32-S3 4.3C 硬件 | 展示设计、驱动或阶段成果，不作为 Demo 必做项 |

## 六、风险与应对

| 风险 | 应对 |
|---|---|
| 前后端字段或权限冲突 | 以契约为准，联调阶段补复现用例，合并前交叉审核 |
| 语音或模型接口不稳定 | 允许降级与人工继续共读，Mock 与真实调用记录分开标注 |
| 绘本图片或审核状态不完整 | 先核验素材与状态，缺图显示真实错误或占位，不绕过权限 |
| 公网部署与数据库恢复有差异 | 先做本地 HTTPS 与恢复预演，再独立验证公网 |
| 硬件上板时间不确定 | Web 独立交付，硬件按编译、Mock、真机分阶段验收 |
| 贡献难以量化 | 任务点与 PR、测试、原型、素材、评审、视频共同作为证据 |

## 十、项目亮点

1. 不是演示版，是能访问的网站。
知芽现在有公网 HTTPS 地址，桌面端和 `mobile.html` 使用同一套 API。部署不是手工上传：PR 先跑校验，合并后由香港机器定时拉取、备份 SQLite、切换镜像并写回执，GitHub Actions 再从公网核对版本、健康接口和匿名后台必须 401。

2. 共读闭环真的跑通了。
从选书到小结，每一步都落库：会话有 `revision`，互动有事件与引用，结束阅读时会话终态、总结、可重放响应同事务写入。现场演示时，翻页、提问、回答、查看记录是连贯的，不是四个孤立的页面。

3. Agent 输出有依据、有边界。
领域知识共 20 条，带来源、适用年龄与任务标签；检索只读已审核版本，生成结果经过安全校验，互动记录里能查到这次用了哪条知识。模型不可用时，会退到预设问题或文字回答，而不是卡住。

4. 内容工程做得扎实。
20 本团队原创绘本、104 页内页，逐页核对画面与文字是否一致（比如《图书馆的小老鼠》第 4 页"小书车"画成了木梯，已列入修改）；20 条知识条目全部可追溯来源。这部分工作不显眼，但它决定了 Agent 回答像不像"懂绘本"。

5. 测试不是最后补的。
后端 198 个用例、96% 行覆盖，前端 71 项，另有 41 项黑盒验收和 12 条缺陷台账。测试文档、缺陷表、模型对比方案都在仓库 `qa/p6` 与 `docs/testing` 下，可以复跑。

6. Vlog 讲出了团队的样子。
4 分 19 秒，用"逆转裁判"式的每日站会开场，中间插入真实讨论、Git 提交记录和成员采访，最后落到每个人的一句话。

移动端早期的问题更多：一开始手机端没有登录入口，401 会跳到桌面登录页且回不来；"实机"模式要家长手填儿童档案 ID、故事版本 ID；分支绘本在手机端走不通。这些在 11 月 20—21 日集中修掉了（#76、#78）：家长登录后回到移动首页，单档案自动选中，分支与小结能在手机端走通。

### 3. 仍然存在的问题

前端问题清单在 11 月 20 日梳理了 25 项（高 6、中 15、低 4），高优先级 6 项已在答辩前修完。以下是还没处理、我们已经记录在案的：

| 问题 | 影响 | 计划 |
|---|---|---|
| 两套前端重复实现且开始分叉（F-19） | 同一功能两端行为不一致，改一处要改两遍 | 抽公共组件与状态层，或明确"桌面为主、移动为简"的边界 |
| 核心 store 与页面组件过大（F-20） | 状态机逻辑堆在单文件，维护成本高 | 按会话、互动、内容拆 store，先补测试再拆 |
| 移动端没有路由，刷新与返回丢状态（F-10） | 误触返回要重新进 | 引入轻量路由或 URL 状态 |
| 图片未懒加载、资源偏大（F-21） | 弱网首屏慢 | 响应式尺寸 + 懒加载 + 预加载关键图 |
| 模态框无 Esc、焦点陷阱与焦点恢复（F-13） | 键盘与读屏用户不友好 | 统一 Modal 组件补齐无障碍行为 |
| 错误提示 2.8 秒自动消失（F-16） | 长错误读不完 | 改为可手动关闭，错误详情可展开 |

## 十五、不足与下一步

1. 前端结构要收一次。两套实现分叉、store 过大，是这轮"赶 Demo"留下的最大技术债；下一步先补测试，再拆公共层。
2. 测试要能门禁。CI 现在跑单测和构建，但没有覆盖率门槛，也没有浏览器 E2E 的常态任务；F-23 已记录。
3. 公网需要一次完整复测。v0.2.0 部署验收通过，但 41 项黑盒用例没有在公网重跑，下一阶段补。
4. 模型效果还没真评测。24 例评测集和评分表已就绪，缺 Key 只能 dry-run，不能拿"感觉不错"代替数据。
5. 内容与版权仍要收口。20 本原创绘本可演示，但《逃家小兔》等公开出版物仍是草稿；上线前要换成原创或明确授权素材。
6. 硬件不夸大。H01 只做到最小工程与启动自检，离"真机联动"还有距离。
