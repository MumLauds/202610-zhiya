# Yaya Agent 2.0 v7.2：对话质量与事实可靠性设计

## 先看 v7.1 的真实失败
86 个真实回执里有 5 个 QUESTION_FORMAT，不等于 5 个误拦。叶子像小船场景是独立的语气回应；两条邮局表达为疑问式推想（其中一条还叠加另列追问），一条正文与另列追问逐字重复，小兔送信则正文先正确作答、再藏入实际追问。v7.1 把正文问号和追问栏格式混在同一个回退判据下。留出集「小澄按住草帽」则是事实层问题：书中写了风、绿丝带和按草帽，未写他是因为害怕；它以前没有被 QUESTION_FORMAT 拦截。

## 最小改动
- 协议 B、同一个 Qwen 模型、Provider、访问进度、时间预算、暂停恢复和追问总额度不改。旧 v6 入口和旧投影函数默认行为原样保留，新质量策略由隔离 v7 演示启用。
- 第一关保留严格协议解析；第二关判断正文有没有索答。独立的语气感叹、明确引述中的问号可保留；未知正文疑问句和可识别的无问号索答按原回退。只使用小范围排版和语言指示，不尝试把 Python 做成通用语义模型。无法判定的问句记录 BODY_INTERROGATIVE_UNRESOLVED；边界外没有问号的隐含索答仍可能漏判。
- 正文完整、但**另列**追问的问句形态、额度或逐字重复检查失败时，不展示另列追问，原正文逐字展示，记录 REPLY_ONLY 和原因；不虚构新台词。实际展示内容进会话，无显示问题不进待答或额度。若正文自己夹带追问，如小兔案例，仍回退；不按标点自动剪句。协议本身无效仍回退。
- 独立字段保留原草稿/原动作、展示决定、实际回执及未执行/已执行独立核验状态。规则通过不等于事实通过。仅展示合成案例，不改变生产逻辑。
- Prompt 做一次通用收紧：动机、心理、归属、动作对象和进展按原文区分；推测可自然说，不要求逐句引证或预先规定台词。没有针对任何一本书或某个孩子输入的运行时分支。是否真正减少无依据补写，以新的 Qwen 回归及单人审阅确认。

## 书证和核验单独推进
已把 28 项与整页原文逐项核对，发现 1 项动作错误、2 项需要澄清。新候选与原索引并存，未取得真人核签，不替换默认书证。复跑已同时检查页序和证据 ID。见 v72_fact_report.md。对既有 18 条单人意见拆分事实/交互/偏好，保留原始评判。独立 Astra 案头诊断不读参考答案，不是第二名人工，也不是实时核验；不接展示链路。

## 两类实验分开
- 旧投影回放：用已发生的访问次数与历史，不将新决定反馈到旧历史，仅比较相同草稿如何展示。无新请求，不能用来衡量 Prompt 或事实改善。
- 真 Qwen 回归：4 个原剧本，16 个调用位置（纸信、叶子船、说星星的是谁、是否送达）；新一批只用自己的实际回执滚动，不重跑 86 次。历史证据差异：v7.1 专项与开发目录四页的原文相同但部分结构化标签不同，本次明确使用冻结的开发版书证进行所有四剧本；原始上下文两侧保留，差异不能只归因于 Prompt。12 个新开发剧本另作 14 轮 Mock。
- 实测之后按 case/turn 核对原文、人物、动作对象、已经发生/尚未发生、想象和推测，保留原草稿和投影。自然度等主观指标以原先的一名真人为上限，不另找第二位、不将旧答卷当成新版评价。区分 API 与浏览器耗时。
