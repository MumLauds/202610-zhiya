# 怎么知道芽芽是在接话，不是在背答案？

**本包的 12 段是开发剧本，不是正式考试题。** 先让同一个模型、同一套提示词完整走过不同绘本、页码和 3–5 轮交流，检查它实际说了什么、系统有没有把这句展示出来。不能用按钮可点、结构合法或 Mock 成功次数替代质量结果。

## 先整理证据

1. 按 README 启动服务，使用全新的 `--record-dir`。如需真实页面等待时间，在前台浏览器走完整段并下载本会话的计时 JSON。命令行重放只产生服务端证据。
2. 正常退出服务器，等待迟到的上游结果写完；不要一边追加一边封存。保留原始 `v6-evidence.jsonl` 和所有浏览器下载。每批一个新目录，不拼接 v5 或不同模式的数据。
3. 例如在项目目录执行（`result-01` 必须不存在；`--page` 按实际文件增减）：

```shell
python eval_v6.py report run-01/v6-evidence.jsonl result-01 --page page-01.json --page page-02.json --blind
```

没有页面下载就删掉 `--page` 参数；没有真实 API 结果就不要加 `--blind`。程序绝不发 API 请求。`report.json` 内保存来源文件 SHA-256、每轮上下文和关联键，以及汇总。完整原始 API 正文和 SDK 请求仍以原始 JSONL 为准；如移交结果，**同时移交原始文件**。请求/上游/回执/页面用会话和轮号关联，校验模式、页与访问序号、上下文中的实际发言和历史、前序服务回执、系统提示词指纹、实际请求及原始响应哈希（有记录时）。混用或内容不符时报错，不改写证据。哈希不是对供应商或文件作者的身份认证。

| 数据 | 能说明什么 |
| --- | --- |
| 上游原始响应与草稿 | 模型实际生成的内容。即使迟到，草稿仍保留，但不计作已展示。 |
| 独立核验 | 本轮未自动做独立事实核验；明确为 NOT_PERFORMED 或未知。两人阅读后的评语另存，并非生产放行。 |
| 服务端回执 | 实际提交到**服务端**会话历史中的句子，标明模型/模拟/回退。 |
| 浏览器展示 | 前台提交到页面完整展示的计时和已显示文字；客户端回退可能与服务端不同；没有页面文件一律记缺测。 |

**统计口径：** 只有 LIVE 且观察到 Provider 实际请求体的上游事件才计入已观测 API 调用；保留 UPSTREAM_BUSY、错误、超时、缺失事件，不从请求书写数猜实际调用数。分别报告服务回退、格式问题和页面回退；服务器 4.1 秒预算触发与供应商 API TIMEOUT 不混为一类。Token 小计同时给出有用量的调用数。输入/输出每百万 Token 单价须按本实验地域、模型、阶梯**自行核对后**用 `--usd-per-million 输入单价 输出单价` 提供；仅在所有已观测真实调用用量齐全时，对这些调用估算。若未提供、用量缺失，或存在未确认请求以致总额不明，不把估算当账单。API、服务端、页面各算一组；后台标签页不算前台等待时间。少于 20 个有效样本不报 P95，更多样本也只代表该批实测。

## 两位真人如何打分

- 只把生成的 **盲评-甲.html** 发给第一位，**盲评-乙.html** 发给第二位。两人独立完成，不讨论、不看评分对照文件；不要把私有映射 `blind-key-private.json` 交给评审。两份顺序独立打乱，不展示模型名称、开发案例标签或期望动作。
- 点开一段，先读该页原文、孩子在回答的问题、原话和模型草稿。想知道下一轮为何如此，展开「系统实际上返回了什么」：回退不是芽芽自己说出来的回答。每段按六项各给 1–5 分；不适用或没有依据选「无法判断」。逐轮四项观察可选「是/否/无法判断」，未填是缺项，不是“无问题”。可以在依据中指出轮次和具体原句。
- 各自在浏览器点「导出我的评分」；甲乙两人都交回后再合并。不要重新生成两份表或复制一个人的评分：

```shell
python eval_v6.py merge result-01/blind-key-private.json 芽芽评分-甲.json 芽芽评分-乙.json 盲评汇总.json
```

合并产物保留个人分数、逐轮观察和原话依据，另列每维有效双人分母、平均分、同分及相差两分以上的数量；先读分歧最大的对话，不用平均分抹掉事实错误。不同批次、重复评审编号、缺掉对话或无效分数都会被拒绝；评审是否为两个独立真人由组织者核实，软件不能证明。

## 如何避免“12/12 就是理解了”

1. 任一开发失败先保留原样；不要把孩子的句子、标准答案、案例编号或逐例提示加回生成路径。
2. 冻结模型 ID、参数、提示词、运行代码、原始开发语料、评分表。让未参与 Prompt 调整的作者在仓库外保管全新合成绘本/表达，固定 SHA-256。不要把真实儿童输入换个说法后拿来测。
3. 在同一环境用 `--v6-fixtures` 和 `--v6-fixtures-sha256`（参数见主 README）加载新合成材料，一次性完整运行、封存后交给两位独立评审。覆盖孩子在同一语境里改口、意思相近但表达不同、字面相同但意图不同、想象和书证、停问后主动恢复等变化，不要求匹配固定台词。
4. 软件产物固定标记 **DEVELOPMENT_ONLY**。即使组织者选用未见材料，文件名或 SHA 也不能证明独立性；在另存的验收说明中附冻结记录、独立作者与双人盲评的实际完成情况、批次和分歧，才能称为留出评测。没跑、没人评、没有页面样本时如实留空，不发表泛化或正式安全结论。
